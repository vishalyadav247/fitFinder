# Storefront

**Prototype:** `design/scripts/screens/storefront.js` · Styles: `design/styles/storefront.css` · **Suggested route:** `/app/storefront`

## Wording per store type
Default texts use the store type's word for what it sells: Automotive "parts", Phones "accessories", Beauty and Something else "products" (e.g. button "Show parts" / "Show accessories" / "Show products", "See … that fit", "No … fit this selection yet."). Other fixed texts ("Reset", "Show all {n}", "Selected", "Add a {noun}", the hover hint) stay fixed for now and use the store type's noun; they can become editable later if needed.

## Purpose
Turn the search on in the live theme and set how the shopper-facing blocks look and behave, with a live preview.

How: "Show {products}" asks the app proxy for one SKU per fitting product (linked rows + universal products) and opens `{locale root}search?type=product&options[prefix]=none&q=variants.sku:"A" OR variants.sku:"B" …`. When nothing fits, or only SKU-less products fit, the link searches `variants.sku:"sparefit-no-match"`, so the theme shows its own "no results" page. If the app proxy can't be reached, SpareFit's page opens. SpareFit's own results page (chosen with **SpareFit's results page**: `/apps/sparefit/results`; SpareFit's own product cards; Search & Discovery filters are not available there; the selection can be given by field name, e.g. `?make=Tata&model=nexon&engine=1.2` (lower-case name, other characters as `-`), or by field id; its page links use the names; in the theme layout: heading "{Products} that fit your {noun}", product cards (rows per page × products per row, up to 20), "No {products} fit this selection yet."). No "save your selection" prompt after a search (removed 2026-10-15); shoppers save from the widget or My Selection. Opened without a full selection (e.g. "Add a {noun}" on a page without the widget), SpareFit's page shows the widget and "Select your {noun} to see the {products} that fit." The search button needs every **required** field (Search setup) and at least one pick; for optional fields a row without a value fits any pick.

### Fits badge tab and Fitment table tab (product page)
- Two tabs, each with its settings on the left and its own preview on the right. No on/off here: both are app blocks, added or removed with **Add to theme** in Theme integration. No position setting: the merchant places the blocks in the theme editor.
- Previews: green **Live preview** badge + a note. Badge preview ("All three states, as shoppers see them."): the three states stacked with small captions, in the order shoppers meet them (Before a selection · When it fits · When it doesn't fit). Table preview ("An example using the first rows of your filter data." / shortcode: "Where you paste the shortcode. An example using the first rows of your filter data."): a product with rows and a product with none.
- **Fits badge** — "Tells shoppers on the product page whether it fits what they picked. Place it in the theme editor, usually above Add to cart."

In the theme editor only (`request.design_mode`), the badge stays visible ("before a selection" state, no note) and a table that would be hidden shows as with "Show a text instead" (title + the empty text), with no notes, so merchants can see and place the blocks on any product.
  - Settings in groups, separated by `s-divider`, so each option sits with the state it affects (in the order shoppers meet them):

    - **When it fits**: **Text** (default "Fits your {noun}").
    - **When it doesn't fit**: **Text** ("Doesn't fit your {noun}") · `s-checkbox` **Show a link to {products} that fit** (on) · **Link text** ("See parts that fit"; links to the search results for the shopper's selection).
    - Products SpareFit doesn't cover (no rows and not universal, e.g. gift cards) show no badge.
    - Last: `s-checkbox` **Show the shopper's selection under the text** (on; applies to fits and doesn't fit; the example shown is the store's own first selection). The selection reads every picked value in dropdown order, e.g. "Renault 2012 Megane III 1.5 dCi" (changed 2026-10-19: it used to show only the year, the first and the last dropdown, so a Model between them was missing). The results page heading and the My Selection tab use the same text; My Selection's saved cards keep their two-line layout. One look only (no style choice): soft background — green when it fits, red when it doesn't, light blue (Polaris info) before a selection.
- **Fitment table** — "Lists everything this product fits." (In block mode, under Where to show it: "Sits with your product page's description and specification rows: drag it between them in the theme editor.") Settings in groups separated by `s-divider`:

The app embed script finds the shortcode on product pages and replaces it with the live table. Never described as "tabs only". The tab shows a 3-step box "Add the shortcode in 3 steps" (pick where the table should go · paste the shortcode, with a **Copy** button (toast "Copied [sparefit-table]") · save) + "Needs the app embed" + **Open theme editor**. Show as / Title / Start expanded are hidden ("The shortcode shows just the table. Add a heading above it in your theme if you want one."); Table style, Columns, Rows and "When a product has no rows" still apply. Preview: the plain table, as for the block ("Where you paste the shortcode. An example using the first rows of your filter data.").
    - Theme integration row then reads Type **App block / Shortcode** (always, either way), Placement "Product page", Status **Active** (code found) / **Not added** (real app: scan the product template's settings for the code), Action: underlined link **How to add →** (opens this tab).

  - **Rows** (the two selects side by side): `s-select` **Sort by** (Search field order (A–Z) / Newest {year field} first, when there is a year range field) · **Rows before "Show all"** (5 / 10 / All; longer lists end with "Show all {n}").

  - Alternative for merchants who want it inside an existing tab: SpareFit also writes each product's fit list to a product metafield (`sparefit.fits`, rich text or JSON). Themes with dynamic sources can connect that metafield to their own collapsible tab.

### My Selection tab (the saved-selections feature)
- **Part of the app embed**, not a block: fixed to the shopper's browser window on every page (`position: fixed`). Nothing to place in the theme. ## Errors and edge states
- Theme access not granted yet (`read_themes` added after the store installed the app): warning banner "SpareFit needs access to your themes" — "SpareFit checks your themes to show whether its blocks and app embed are added. Open SpareFit from your apps list and approve the updated permissions, then come back to this page." Other read failures: critical banner "Your themes couldn't be read" — "Reload the page to try again." Either way the feature table stays visible with Status **Not checked** (no theme picker or App embed switch; My Selection's switch shows but stays disabled).
- While a theme is checked: a spinner in Status; if the check fails: tertiary button "Couldn't check. Try again".
- **Save bar:** every setting change (including My Selection's switch in Theme integration) goes into a draft that the live previews show right away, and opens the App Bridge save bar (Save / Discard, with Shopify's discard confirmation). **Save** sends all changes in one request → toast "Settings saved" (failed: error toast, the draft stays). Changes made while a save runs stay in the draft. **Discard** puts the saved settings back. **Edit fields** asks first (`shopify.saveBar.leaveConfirmation()`) while there are unsaved changes. The icon upload is saved straight away (toast "Icon uploaded").
- Copy failed: error toast "Couldn't copy. Select the code and copy it."
- Icon upload: "Uploading…" under the drop zone; errors on the drop zone ("Choose an SVG or PNG file.", "The file is larger than 100 KB.", "The icon must be square and at least 48 × 48 px.", "The icon couldn't be uploaded. Try again."); success shows "Icon uploaded." (no toast).
- No filter rows yet: the table preview says "No filter rows yet. Import some to see sample rows."; badge and My Selection previews use the field names as the example selection.

## Data / backend
- Themes: GraphQL `themes(first: 20, roles: [MAIN, UNPUBLISHED, DEVELOPMENT])` (MAIN = live; listed live first). Needs `read_themes`. Status per theme (`GET /api/themes/{id}`, cached in `theme_status`): read `config/settings_data.json`, `templates/*.json` and `sections/*.json` with `theme.files(filenames:)`. App embed on = our `sparefit-embed` block in settings_data with `disabled` not true; a block counts as added when it sits, not disabled, in a section that isn't disabled (nested blocks too); "View in editor" opens the template it was found in and shows a toast naming the section it sits in ("Theme editor opened. Fits badge is in the Product information section."; Shopify has no deep link that selects an existing block). The name is the merchant's own section name, else the section's schema name (a `t:` key looked up in `locales/en.default.schema.json`), else its type; only those section files are read, and a failure just gives "Theme editor opened." Code found = `[sparefit-table]` in a product template or section group. Read again when the merchant picks a theme and when the window gets focus (back from the theme editor).
- Theme editor links (open in a new tab): editor `https://{shop}/admin/themes/{id}/editor`; embed on `?context=apps&activateAppId={api_key}/sparefit-embed`; embed off `?context=apps`; add Search section `?template=index&addAppBlockId={api_key}/sparefit-search&target=newAppsSection`; add Fits badge / Fitment table `?template=product&addAppBlockId={api_key}/sparefit-fits-badge|sparefit-fitment-table&target=mainSection`.
- `PUT /api/storefront-settings` — the save bar's Save: `{ intent: "save", settings: { key: JSON value }, heading? }` (every value is checked first; one write, one publish). Also `{ intent: "setting", key, value }` (one key of `EDITABLE_KEYS` in `app/services/storefront/settings.ts`, merged into the shop's JSON document), `{ intent: "heading", value }` (search_configs.heading) or `{ intent: "publish" }`. Texts are trimmed, 1–200 characters; leaving a text field empty puts the saved text back. Each save publishes the config to the app metafield; if that fails the page shows a warning banner "Your theme doesn't have the latest settings yet" with **Try again**. Publishes are serialized per shop.
- `POST /api/storefront-icon` — custom My Selection icon: checked on the server (PNG/SVG bytes, square, ≥ 48 px, ≤ 100 KB, no scripts in SVGs), uploaded to Shopify Files (`stagedUploadsCreate` → upload → `fileCreate`, PNG as image, SVG as generic file; needs `write_files`), then saved as `savedIcon: custom` + `savedIconUrl`. **Remove** clears the URL (the file stays in Shopify Files).
- Settings reach the theme extension through the app-data metafield `sparefit.config`, so blocks render without an extra request.
- The first dropdown's values (agreed 2026-10-13) go to their own app-data metafield `sparefit.first` (`{ f: fieldId, v: string[] | null }`), printed only by the search block, so opening a page with the widget asks the app proxy nothing and touches no database, and other pages don't carry the list. The widget uses it only while `f` is still the config's first field and `v` is a list; otherwise (no list, field order changed and not yet republished) it asks `/options` as before. Only the background job `storefront-publish` computes it (admin requests just compare a cheap key: install time, data version, first field, year, in `storefront_settings.first_published`, and queue the job); imports queue it when they finish. Lists over 16 KB, and values queries that fail (30 s timeout, outside the storefront query slots), publish `v: null`. Until the job lands (seconds), shoppers see the previous list; a new year is picked up at the next admin visit.
- Previews: sandboxed iframes running the theme extension's own stylesheets (`sp-embed.css` plus `sp-search.css` or `sp-product.css`, as on that storefront page) and scripts with the unsaved settings; their app proxy calls go to `GET /api/storefront-preview?path=options|results`. Sample rows and the example selections are the shop's first filter rows (the field names when there are none). Previews rebuild shortly after each change; the search widget keeps its picks.

## Theme app extension (real app)
- App embed block: loads the script and garage state.
- Stylesheets per place (M10): `sp-embed.css` (every page: My Selection, ~6.6 KB; loaded without blocking rendering, the button stays hidden until it has loaded), `sp-search.css` (search section, results page), `sp-product.css` (badge, table). Pages without a block (SpareFit's results page, the code in theme tabs) get the block's script and stylesheet from the app embed.
- Block files (handles): `sparefit-embed` (app embed), `sparefit-search` (added as its own section on any template), `sparefit-fits-badge` and `sparefit-fitment-table` (inside the product info section). The `sparefit-` prefix keeps them apart from other apps' blocks when reading a theme. The saved-selections floating button is rendered by the app embed (fixed position), so it works on every theme.
- Storefront API via app proxy `/apps/sparefit/*`: `options`, `results`, `fits` (see [data-model.md](data-model.md)).
