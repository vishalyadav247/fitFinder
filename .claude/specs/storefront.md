# Storefront

**Prototype:** `design/scripts/screens/storefront.js` · Styles: `design/styles/storefront.css` · **Suggested route:** `/app/storefront`

## Wording per store type
Default texts use the store type's word for what it sells: Automotive "parts", Phones "accessories", Beauty and Something else "products" (e.g. button "Show parts" / "Show accessories" / "Show products", "See … that fit", "No … fit this selection yet."). Other fixed texts ("Reset", "Show all {n}", "Selected", "Add a {noun}", the hover hint) stay fixed for now and use the store type's noun; they can become editable later if needed.

## Purpose
Turn the search on in the live theme and set how the shopper-facing blocks look and behave, with a live preview.

## Layout
`s-page heading="Storefront"` · primary **Open theme editor**.

1. *(When the live theme's app embed is off, whichever theme is selected)* `s-banner tone="critical"` "FitFinder is turned off in your live theme" — "Shoppers don't see My Selection or the fitment table shortcode, and blocks can't be added, until you turn on the app embed in Theme integration." (Search sections already on the theme keep working: they load their own script.)
   *(When the theme publish failed)* `s-banner tone="warning"` "Your theme doesn't have the latest settings yet" — "FitFinder couldn't send your changes to the theme." + **Try again** (toast "Theme updated" or error "The theme couldn't be updated. Try again later.").
2. **Theme integration** (`s-section padding="none"`, title "Theme integration" on top: Polaris heading size (14px) but bolder (750))
   - Top row: `s-select` **Theme** (the store's themes, e.g. "Dawn (live theme)", "Refresh (draft)"; default the live theme) and, on the right on one line, **App embed** + On (success) / Off (critical) badge + `s-switch` (no description, no box).
   - The App embed switch does **not** change the theme itself (Shopify doesn't allow apps to). It opens the theme editor of the selected theme on the App embeds panel with FitFinder ready to enable: `https://{shop}/admin/themes/{themeId}/editor?context=apps&activateAppId={api_key}/{embed_handle}`. Turning it off opens the same panel. When the merchant returns (window focus), re-read the embed status from the theme's `config/settings_data.json` and update the badge and switch. The prototype flips the switch straight away and shows the toast "Theme editor opened. App embed turned on (simulated)"; the app shows "Theme editor opened. Turn on FitFinder there and save." (off: "…Turn off FitFinder there and save."), opens the editor in a new tab and leaves the switch as it was until the status is read again.
   - Not the live theme → info `s-banner` "{theme} isn't your live theme" — "You can set FitFinder up here now. Shoppers see it once you publish this theme."
   - `s-table` of what goes into the theme. **Type** is the Shopify theme type: **Section** (placed on a page by the merchant) or **App block** (sits inside an existing section).
     | Feature | Type | Placement | Status | Action |
     |---|---|---|---|---|
     | Search section | Section | Home, collection, product or any other page | Active (success) / Not added | underlined links like **How to add →**: **View in editor →** / **Add to theme →** (opens the theme editor with the block inserted; plain grey text while the embed is off or there's no theme) |
     | Fits badge | App block | Product page | 〃 | 〃 |
     | Fitment table | App block / Shortcode | Product page | 〃 | 〃 |
     | My Selection | App embed | Floating button on every page | Active (success) / Off / Needs app embed (warning) | the on/off `s-switch` only |
   - No progress badge or intro line. Everything applies to the selected theme. **Open theme editor** (page primary action, external icon) opens the editor of the selected theme; **Add to theme** / **View in editor** deep-link to that block.
3. Tabs (segmented bar in the card style; icon per tab, Sky when active): **Search widget** (search) · **Fits badge** (check-circle) · **Fitment table** (table) · **My Selection** (star).
4. Each tab: preview header with **Desktop / Mobile** toggle, a mock browser window showing the storefront, then settings sections.

### Search widget tab
- Preview, titled with a green `s-badge tone="success"` **Live preview** (Desktop / Mobile): the widget as shoppers see it — real cascading `<select>`s, button, "Save to {name shoppers see}", Reset. Results show matched products with "✓ Fits your {noun}" and `[price]`. Every setting below updates the preview right away.
- **Layout and style**
  - `s-select` **Layout**: Horizontal (one row) / Vertical (stacked) — details "On phones the dropdowns always stack." · `s-select` **Corners**: Square / Rounded / Pill.
  - `s-color-field` × 3: **Button colour**, **Background**, **Text colour** (heading, labels, save link; the reset link uses the button colour).
  - `s-checkbox` **Show labels above the dropdowns** (off by default) — "Off: the field name is shown inside each dropdown instead."
- **Text** and **Behaviour** sit side by side (Text left, about two thirds; Behaviour right).
- **Text** (one column)
  - **Search heading** (e.g. "Find parts for your vehicle"; the only place to set it) with `s-checkbox` **Show search heading** (on) right under it.
  - **Button text** · **Save link text** (default "Save to My Selection"). Dropdown placeholders are set per field on Search setup.
  - "Dropdowns and their placeholder text come from your search fields:" + field chips + **Edit fields** (→ Search setup).
- **Behaviour** — only two `s-checkbox`es: **Show "{save link text}"** (on) and **Show a reset link** (on). The save link has its own setting, separate from the floating saved-selections button.
  - Results always open on the theme's own **search page**, filtered to the parts that fit (no choice shown), so shoppers get the theme's own product cards and its existing filters and sorting (Search & Discovery). FitFinder has no filters of its own (agreed 2026-10-05). How: "Show {products}" asks the app proxy for one SKU per fitting product (linked rows + universal products) and opens `{locale root}search?type=product&options[prefix]=none&q=variants.sku:"A" OR variants.sku:"B" …`. Products without a SKU can't be searched for and are left out. When nothing fits, only SKU-less products fit, or the list is longer than one search takes (100 SKUs / 6,000 characters), FitFinder's own results page opens instead (`/apps/fitfinder/results`, in the theme layout: heading "{Products} that fit your {noun}", the selection, linked collections, product cards, 16 per page, "No {products} fit this selection yet."). After a search, "Save {selection} to {name}?" with **Save** and a × close appears at the top of the results, once per selection (setting "Ask shoppers to save their selection after a search"). Opened without a full selection (e.g. "Add a {noun}" on a page without the widget), FitFinder's page shows the widget and "Select your {noun} to see the {products} that fit." The search button needs every **required** field (Search setup) and at least one pick; for optional fields a row without a value fits any pick.
- Every preview (Search widget, Product page, My Selection) is titled with the same green `s-badge tone="success" icon="view"` **Live preview**.
- Plain Polaris controls only (no custom segmented buttons or colour swatches). The Search widget preview has a Desktop / Mobile switch as two icon buttons (`icon="desktop"` / `icon="mobile"`; the selected one is secondary, the other tertiary); the Product page and My Selection previews look the same on both and have no switch. Previews show only FitFinder's part — no backdrop, padding, store bar or placeholder content (My Selection uses a small browser window to show the fixed position).

### Fits badge tab and Fitment table tab (product page)
- Two tabs, each with its settings on the left and its own preview on the right. No on/off here: both are app blocks, added or removed with **Add to theme** in Theme integration. No position setting: the merchant places the blocks in the theme editor.
- Previews: green **Live preview** badge + a note. Badge preview ("All three states, as shoppers see them."): the three states stacked with small captions, in the order shoppers meet them (Before a selection · When it fits · When it doesn't fit). Table preview ("An example using the first rows of your filter data." / shortcode: "Where you paste the shortcode. An example using the first rows of your filter data."): a product with rows and a product with none.
- **Fits badge** — "Tells shoppers on the product page whether it fits what they picked. Place it in the theme editor, usually above Add to cart."
- **Theme editor preview:** on a product without filter rows (and not universal) shoppers see no badge and no fitment table. In the theme editor only (`request.design_mode`), the badge stays visible ("before a selection" state, no note) and a table that would be hidden shows as with "Show a text instead" (title + the empty text), with no notes, so merchants can see and place the blocks on any product.
  - Settings in groups, separated by `s-divider`, so each option sits with the state it affects (in the order shoppers meet them):
    - **Before a selection**: **Text** ("Select your {noun} to check if it fits").
    - **When it fits**: **Text** (default "Fits your {noun}").
    - **When it doesn't fit**: **Text** ("Doesn't fit your {noun}") · `s-checkbox` **Show a link to {products} that fit** (on) · **Link text** ("See parts that fit"; links to the search results for the shopper's selection).
    - Products FitFinder doesn't cover (no rows and not universal, e.g. gift cards) show no badge.
    - Last: `s-checkbox` **Show the shopper's selection under the text** (on; applies to fits and doesn't fit; the example shown is the store's own first selection). One look only (no style choice): soft background — green when it fits, red when it doesn't, light blue (Polaris info) before a selection.
- **Fitment table** — "Lists everything this product fits." (In block mode, under Where to show it: "Sits with your product page's description and specification rows: drag it between them in the theme editor.") Settings in groups separated by `s-divider`:
  - **Where to show it** (first group): `s-select` **Use as block** (default; app block in any product-page section that supports app blocks; hint "Add it to any section on the product page that supports app blocks, then drag it where you want it in the theme editor.") / **Use as shortcode** (the `[fitfinder-table]` shortcode, pasted anywhere on the product page).
    - Shortcode: the merchant pastes `[fitfinder-table]` into any spot of the product page that shows text (a text or Custom Liquid block, a collapsible row, a tab …). The app embed script finds the shortcode on product pages and replaces it with the live table. Never described as "tabs only". The tab shows a 3-step box "Add the shortcode in 3 steps" (pick where the table should go · paste the shortcode, with a **Copy** button (toast "Copied [fitfinder-table]") · save) + "Needs the app embed" + **Open theme editor**. Show as / Title / Start expanded are hidden ("The shortcode shows just the table. Add a heading above it in your theme if you want one."); Table style, Columns, Rows and "When a product has no rows" still apply. Preview: the plain table, as for the block ("Where you paste the shortcode. An example using the first rows of your filter data.").
    - Theme integration row then reads Type **App block / Shortcode** (always, either way), Placement "Product page", Status **Active** (code found) / **Not added** (real app: scan the product template's settings for the code), Action: underlined link **How to add →** (opens this tab).
    - Backend note: also write each product's fit list to a product metafield (`fitfinder.fits`) for developers and SEO; it is not offered in the UI.
  - **Display:** `s-select` **Show as** (Collapsible row / Open table) · **Title** (default "Fits these {noun}s") · `s-checkbox` **Start expanded** (collapsible only; on) · `s-select` **Table style** (Lines between rows (default) / Striped rows / Plain).
  - **Columns:** "One column per search field, in the same order as Search setup." + an `s-checkbox` per search field (all on; the last one left on can't be turned off).
  - **Rows** (the two selects side by side): `s-select` **Sort by** (Search field order (A–Z) / Newest {year field} first, when there is a year range field) · **Rows before "Show all"** (5 / 10 / All; longer lists end with "Show all {n}").
  - **When a product has no rows:** Hide the table (default) / Show a text instead + **Text** (default "Fits all {noun}s"; "Useful for universal products.").
  - Preview ("An example using the first rows of your filter data." / shortcode: "Where you paste the shortcode. An example using the first rows of your filter data."): "Product with rows" (a few sample rows so sorting, columns, limit and style are visible) and "Product with no rows" (nothing, or the text).
  - Why its own row: Shopify doesn't let an app block go inside a theme's collapsible tab, so the block draws its own collapsible row styled like the theme's and the merchant drags it between the theme's rows.
  - Alternative for merchants who want it inside an existing tab: FitFinder also writes each product's fit list to a product metafield (`fitfinder.fits`, rich text or JSON). Themes with dynamic sources can connect that metafield to their own collapsible tab.

### My Selection tab (the saved-selections feature)
- **Part of the app embed**, not a block: fixed to the shopper's browser window on every page (`position: fixed`). Nothing to place in the theme. In the Theme integration table (feature **My Selection**) it shows Type **App embed**, Placement "Floating button on every page", Status **Active** / **Off** / **Needs app embed** (warning), Action: only an `s-switch` to turn it on/off (the only on/off control; disabled while the app embed is off). Its settings are in this tab.
- **Closed:** a tab with an icon (side edges: shoppers can drag it up or down, 10–90% of the window; a drag of 6px or more isn't a click; the spot is kept in their browser), the shopper's current selection (e.g. "2008 AUDI A6 C6 Avant (4F5)"; before anything is saved: the name) and a count badge (always upright, reads left to right; can be turned off). The icon is 24px and on the vertical tabs turns with the text. Long text is cut with "…" (full text in the tooltip). Side edges: vertical tab 46px wide and as tall as its content, at most 190px (no blank space when there's no count), flush with the window edge (text reads bottom to top on the right, top to bottom on the left). Bottom corners: pill 46px high and as wide as its content, at most 220px. 18px semibold, in the device's system UI font (not the theme's web font, which can swap in late and change the weight).
- **Hover only:** the hint card is `display: none` until the tab is hovered (it can never show while the page loads) and then fades in (0.25s animation). The tab keeps its size and position (no slide, no grow), only its shadow deepens, and a dark hint card appears next to the tab: "SHOPPING FOR" (small green caps) · the current selection (bold, cut with …) · "2 saved · Click to switch or add". Before anything is saved: "{name}" · "Save your selection here" · "Click to add your first one".
- **Open (click):** the tab fades out and a 280px panel slides in from the same edge (0.35s ease-out). The panel and its close tile have a 1px border in the tab's background colour (green #74F821 by default). Close = a small rectangular tile on the panel's inner edge, in the middle (30 × 64px; on top for bottom positions), with an arrow pointing back to the window edge. Title = the name in capitals ("MY SELECTION"), one card per saved selection (year + first field in bold 15px, last field below in grey; trash icon on the right). The active one has a green border and a green "Selected" pill. With nothing saved, a dashed box "Nothing saved yet" — "Search, then save your selection to find it here next time." sits above the button. Full-width **Add a new selection** button: background = the text colour setting (dark by default), label always white. Close slides it back.
- Layout: settings on the left, preview on the right. Preview: the green **Live preview** badge with "Hover the tab or click it to try it. Looks the same on desktop and mobile." next to it, then a small browser window with the tab pinned in the chosen position (real hover and click).
- Section **My Selection** — "A floating button that stays in a corner of every page…". Embed off → warning banner "Turn on the app embed to show the button".
- No on/off in this tab (it lives in Theme integration). When it is off: info banner "My Selection is turned off — Turn it on with its switch in Theme integration above. You can still set it up here."
- Settings: **Name shoppers see** (default My Selection) · `s-select` **Position**: Right edge, middle (vertical tab, default) / Left edge, middle (vertical tab) / Bottom right / Bottom left · `s-select` **Icon**: Star / Heart / Bookmark / Clock (recent) / the store type icon (default, e.g. a car) / **Custom (upload your own)** / No icon. Custom shows an `s-drop-zone` "Upload an icon" + "SVG or PNG, square, at least 48 × 48 px, up to 100 KB. Shown at 24 px next to the name." and, once uploaded, "Icon uploaded." + **Remove** (real app: upload to Shopify Files with `stagedUploadsCreate` → `fileCreate`, save the URL) · `s-color-field` **Background colour** (default #74F821) and **Text colour** (default #1A1A1A) · **Saved selections per shopper** (3 / 5 / 10) · `s-checkbox` **Show saved selection count** (on; the number bubble on the button) · `s-checkbox` "Ask shoppers to save their selection after a search".

## Errors and edge states
- Theme access not granted yet (`read_themes` added after the store installed the app): warning banner "FitFinder needs access to your themes" — "FitFinder checks your themes to show whether its blocks and app embed are added. Open FitFinder from your apps list and approve the updated permissions, then come back to this page." Other read failures: critical banner "Your themes couldn't be read" — "Reload the page to try again." Either way the feature table stays visible with Status **Not checked** (no theme picker or App embed switch; My Selection's switch shows but stays disabled).
- While a theme is checked: a spinner in Status; if the check fails: tertiary button "Couldn't check. Try again".
- **Save bar:** every setting change (including My Selection's switch in Theme integration) goes into a draft that the live previews show right away, and opens the App Bridge save bar (Save / Discard, with Shopify's discard confirmation). **Save** sends all changes in one request → toast "Settings saved" (failed: error toast, the draft stays). Changes made while a save runs stay in the draft. **Discard** puts the saved settings back. **Edit fields** asks first (`shopify.saveBar.leaveConfirmation()`) while there are unsaved changes. The icon upload is saved straight away (toast "Icon uploaded").
- Copy failed: error toast "Couldn't copy. Select the code and copy it."
- Icon upload: "Uploading…" under the drop zone; errors on the drop zone ("Choose an SVG or PNG file.", "The file is larger than 100 KB.", "The icon must be square and at least 48 × 48 px.", "The icon couldn't be uploaded. Try again."); success shows "Icon uploaded." (no toast).
- No filter rows yet: the table preview says "No filter rows yet. Import some to see sample rows."; badge and My Selection previews use the field names as the example selection.

## Data / backend
- Themes: GraphQL `themes(first: 20, roles: [MAIN, UNPUBLISHED, DEVELOPMENT])` (MAIN = live; listed live first). Needs `read_themes`. Status per theme (`GET /api/themes/{id}`, cached in `theme_status`): read `config/settings_data.json`, `templates/*.json` and `sections/*.json` with `theme.files(filenames:)`. App embed on = our `fitfinder-embed` block in settings_data with `disabled` not true; a block counts as added when it sits, not disabled, in a section that isn't disabled (nested blocks too); "View in editor" opens the template it was found in and shows a toast naming the section it sits in ("Theme editor opened. Fits badge is in the Product information section."; Shopify has no deep link that selects an existing block). The name is the merchant's own section name, else the section's schema name (a `t:` key looked up in `locales/en.default.schema.json`), else its type; only those section files are read, and a failure just gives "Theme editor opened." Code found = `[fitfinder-table]` in a product template or section group. Read again when the merchant picks a theme and when the window gets focus (back from the theme editor).
- Theme editor links (open in a new tab): editor `https://{shop}/admin/themes/{id}/editor`; embed on `?context=apps&activateAppId={api_key}/fitfinder-embed`; embed off `?context=apps`; add Search section `?template=index&addAppBlockId={api_key}/fitfinder-search&target=newAppsSection`; add Fits badge / Fitment table `?template=product&addAppBlockId={api_key}/fitfinder-fits-badge|fitfinder-fitment-table&target=mainSection`.
- `PUT /api/storefront-settings` — the save bar's Save: `{ intent: "save", settings: { key: JSON value }, heading? }` (every value is checked first; one write, one publish). Also `{ intent: "setting", key, value }` (one key of `EDITABLE_KEYS` in `app/services/storefront/settings.ts`, merged into the shop's JSON document), `{ intent: "heading", value }` (search_configs.heading) or `{ intent: "publish" }`. Texts are trimmed, 1–200 characters; leaving a text field empty puts the saved text back. Each save publishes the config to the app metafield; if that fails the page shows a warning banner "Your theme doesn't have the latest settings yet" with **Try again**. Publishes are serialized per shop.
- `POST /api/storefront-icon` — custom My Selection icon: checked on the server (PNG/SVG bytes, square, ≥ 48 px, ≤ 100 KB, no scripts in SVGs), uploaded to Shopify Files (`stagedUploadsCreate` → upload → `fileCreate`, PNG as image, SVG as generic file; needs `write_files`), then saved as `savedIcon: custom` + `savedIconUrl`. **Remove** clears the URL (the file stays in Shopify Files).
- Settings reach the theme extension through the app-data metafield `fitfinder.config`, so blocks render without an extra request.
- Previews: sandboxed iframes running the theme extension's own stylesheets (`ff-embed.css` plus `ff-search.css` or `ff-product.css`, as on that storefront page) and scripts with the unsaved settings; their app proxy calls go to `GET /api/storefront-preview?path=options|results`. Sample rows and the example selections are the shop's first filter rows (the field names when there are none). Previews rebuild shortly after each change; the search widget keeps its picks.

## Theme app extension (real app)
- App embed block: loads the script and garage state.
- Stylesheets per place (M10): `ff-embed.css` (every page: My Selection and the save prompt, ~6.6 KB; loaded without blocking rendering, the button stays hidden until it has loaded), `ff-search.css` (search section, results page), `ff-product.css` (badge, table). Pages without a block (FitFinder's results page, the code in theme tabs) get the block's script and stylesheet from the app embed.
- Block files (handles): `fitfinder-embed` (app embed), `fitfinder-search` (added as its own section on any template), `fitfinder-fits-badge` and `fitfinder-fitment-table` (inside the product info section). The `fitfinder-` prefix keeps them apart from other apps' blocks when reading a theme. The saved-selections floating button is rendered by the app embed (fixed position), so it works on every theme.
- Storefront API via app proxy `/apps/fitfinder/*`: `options`, `results`, `fits` (see [data-model.md](data-model.md)).
